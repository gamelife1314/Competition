## 一、逐场复盘

## 二、根因定位

### 2.1 P0-A：答案红线只认"整值等于哨兵"，占位符和散文全部漏过

**位置**：`CoreGeek/src/brain/task.rs` — `is_failure_answer()`（:1010）与
`is_sentinel()`（:1144）。（行号是本批改完之后的行号；这一批新增了
`is_placeholder_compound()` :1102 与 `is_prose_fragment()` :1133。）

红线原来的判据是**整串精确等于**哨兵表里的一项。于是下面四类全部穿过，直达判题器，
并且被写进 `best_answer`（也就是超时前兜底提交的那个值）：

| 实际提交 | 出自 | 为什么漏 | 判题器 |
|---|---|---|---|
| `TOKEN_PENDING_MANUAL_REVIEW` | #111 s1 ×3 | 整串不在表里（表里只有 `pending`） | `答案不是合法 JSON` ×3 |
| `，形式：` | #112 s1 ×3 | 4 个字符的中文散文 | `答案不是合法 JSON` ×3 |
| `0写成"0"，否则算错` | #114 s6 ×3 | 11 个字符，抄的是任务文件的说明 | `答案不是合法 JSON` ×3 |
| `{"token": ""}` | #115 | 叶子是空串，`is_sentinel("")` 为假 | 未提交 |

这条不是"模型答错了"，是**我们把它答错的东西交上去了**。`task_answer_found` 日志证明
我们**看见了**这些值（`{"answer": "TOKEN_PENDING_MANUAL_REVIEW", "exit": 0}`），红线的
职责就是在这里拦住它们。

### 2.2 P0-B：喂回给模型的沙盒输出被截到 600 字符，模型因此永远读不到题目

**位置**：`CoreGeek/src/brain/task.rs` — `build_prompt()`（:435）里的
`truncate(result, 600)`，以及 `on_cmd_result()`（:79）里的 `truncate(result, 1200)`。
（两个数字都是**改之前**的值。）

证据链：

1. `cmd_result.chars` 五场都在 **2390 / 3081 / 5467** 这个量级；
2. `build_prompt` 只回放**最后两条**，每条**截 600 字符**——也就是说脚本读到的任务文件，
   只要不在开头 600 字符内，模型**从来没见过**；
3. 于是模型的下一个动作只能是"再读一遍"。`cmd_sent.head` 在 #115 的 r12 / r15 / r18 是
   三份几乎一样的侦察脚本，`task_cmd_failed` 13 条、`exit` 全是 0；
4. 结果就是 #115 整场零提交，以及 #113 那种"判题器说了缺 `token`，下一个脚本还是算不出
   `token`"——**它没读到要求输出 `token` 的那一段**。

`result_history` 里的原文被存成 1200 字符，但 `build_prompt` 又把它砍到 600。
两处叠加，最坏情况下模型看到的是**它自己脚本输出的一份 600 字符摘要**。

### 2.3 P0-C：命令通道的两格日志，让上面两条在两个批次里都查不下去

**位置**：`CoreGeek/src/state.rs`（`cmd_result` 事件，:735）与
`CoreGeek/src/brain/task.rs`（`task_cmd_failed` 事件，:173——改之前是 :148）。

```text
{"data": {"chars": 2390, "requestRound": 12, "session": 1}, "event": "cmd_result"}
{"data": {"exit": 0, "timeout": false}, "event": "task_cmd_failed"}
```

- `cmd_result` 只有**字符数**。脚本返回了 5467 个字符，没有一格说返回了**什么**。
  于是"模型一直在跑侦察脚本"这个结论只能靠 `cmd_sent.head` 的脚本文本去猜，而脚本
  **输出**没有留下任何痕迹。
- `task_cmd_failed` 只有 `exit` / `timeout`。脚本跑完了（exit 0）却不叫 `task_cmd_ok`，
  名字本身就在误导。

这两格是 §2.1 和 §2.2 拖了两个批次才被定位的直接原因。**它们不需要修任何逻辑，
只需要把已有的东西写下来。**

### 2.4 P1：黄昏封门从来没封上，而基地是在夜里被打掉的

`gate_open_record` 只在"每个可操作角色都在家、或已站在它今晚要守的塔的作业格上"时才


这排除了"被封死在环外"，指向**黄昏归位这一段路径规划**（`day.rs` 的

### 2.5 P2：`no_target_reserved_for_robots` 这个名字与它的含义相反

**位置**：`CoreGeek/src/brain/night.rs`（:382-412）与 `CoreGeek/src/brain/combat.rs`

这一格在五场里出现 18 / 43 / 56 / 24 次，名字读起来是"有机器人猎物，被开火纪律压着

这不是一条要改逻辑的缺陷（压火本身是有意的），但**名字会把下一批分析带偏**，和
`task_cmd_failed` 是同一类问题。

## 三、改进方案

排序依据：**能不能证伪 / 值多少分 / 有多危险**。P0 全部落在任务线，因为它们的证据最硬、
改动最局部、且不碰任何一条硬约束。P1 落在封门，因为它值 500 分但动的是寻路。

### P0-1 答案红线：把"占位符"和"散文"补进 `is_failure_answer`

**改哪里**：`CoreGeek/src/brain/task.rs`

1. `is_sentinel()`：空串算哨兵（`{"token": ""}`）。
2. 新增 `is_placeholder_compound()`：**无空格、≤64 字符、能按 `_ - . /` 切成 ≥2 段、
   且每一段都是哨兵或占位词**（`token` / `manual` / `review` / `value` / `status` …）
   ⇒ 是占位符。用"每一段"而不是"某一段"，`failed_to_extract.log`、`error_count=7`、
   `world_heritage_count` 这些真结果原样放行。
3. 新增 `is_prose_fragment()`：**不是合法 JSON、且含中文句读**（`，。；！？、""''`）
   ⇒ 是散文。不含 `《》（）` 和 `：`，中文书名号（《静夜思》）仍然可以当答案。

   **已知边界（故意留的）**：判据停在引号外——裸的 `，形式：` 会被拦，
   `"，形式："` 不会。理由是把"中文答案里带逗号"（诗句、带省份的地名）误杀一次的代价
   （整个任务奖励）比漏掉一个假设的引号形式更大，而这五场里真实出现的两次
   （#112、#114）**都是裸的**。这个边界在两处测试里各钉了一遍
   （`answer_redline.rs` 的 `a_sentence_from_the_task_file_is_not_an_answer`）。

**预期收益（对应 `任务书` 第六章 score_1）**：这四类答案今天**全部得 0 分**，所以拦住
它们不损失任何分数，收益在于两点——(a) 不再把 `best_answer` 污染成占位符（超时兜底
提交的就是它，等于把一个必 0 的答案锁死到最后）；(b) 把那一轮还给真正的重试。
单场按 #111/#112/#114 各烧掉 3 次提交算，**每场省下 3 个回合 × 2 个 session**，
而任务超时回合数只有 24–50 回合。

### P0-2 侦察死循环：把沙盒输出喂够 + 明说"侦察已经结束"

**改哪里**：`CoreGeek/src/brain/task.rs`（`build_prompt` / `on_cmd_result`）、
`CoreGeek/src/state.rs`（`TaskSession::no_answer_rounds`）

1. 回放窗口 `600` → **最后一条 3000 字符、前一条 1200 字符**（`result_history` 的
   单条上限同步提到 3000）。
2. 新增 `no_answer_rounds` 计数器（`on_cmd_result` 里"没找到答案"或"答案被红线拦下"
   都 +1，找到答案归零）。
3. 计数器 > 0 时，prompt 里加一段：**"上一次没有打印 `ANSWER:` 行；侦察已经完成，
   本轮不要再用 find / ls / cat"**；≥2 时升级为"本轮必须打印 ANSWER 行，剩余 N 回合"。

**预期收益（对应 score_1）**：#115 整场 0 提交，四场里另外 4 / 5 / 6 个 session 也是 0
提交。任务点 `scoreReward = 50`，完成时还额外加
`5 × 超时回合数 / 实际回合数`。**把一个"从不作答"的 session 变成一次真实提交，
单场就是 +50 到 +150 分**，而且它是 P0-1 反馈环唯一的入口——没有提交，反馈环就没有作用点。
